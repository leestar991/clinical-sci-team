# 入排标准四分类解析（完整技能包）

本技能自带三域完整执行知识：**①入排拆分**（怎么拆、拆到什么颗粒度）、**②质检**（结构闸 +
语义 QC 两层收敛）、**③修复**（按 QC 类型对号入座的修订）。深水区（完整样例、模板源、
故障档案、同义词表）在 `references/`，本文件每节末尾给出索引；委派 prompt 由
`scripts/render_parse_prompt.py` 机械渲染，规则内嵌，子代理无需读本文。

## 流程总览

```
eligibility_criteria_raw.md + criteria_meta.json（输入，见 §0）
  → 双轨拆分（IN ∥ EX，§1）→ 结构闸自跑到 exit 0（§2.1）
  → 语义 QC ↔ 修复循环，≤3 轮/轨（§2.2 ↔ §3）
  → slim ×2 + assemble（判定输入包）→ phase2_summary（§4）
```

**产物**：`criteria_parsed_IN/EX.json`（各自四分类+描述索引）、`criteria_parsed.json`（assemble
全量）、`criteria_judge_IN/EX.json`（判定包）、`criteria_qc_IN/EX.json`（QC 报告）、
`phase2_summary.json`。全篇级字段（`方案元数据`/`解析说明`/`汇总统计`）只由 assemble 注入，
两轨 ⛔ 禁产。

## §0 输入：章节提取与完整性自检

- 入排原文**逐字完整提取**（宁可多带上下文，绝不截断/概括；保留子项/`注：`/表格/客观判定标准）。
- 定位与自检一律用 `scripts/locate_criteria_sections.py`（⛔ 禁止 `grep -n`/`awk NR` 定位——
  PDF 转出的 `.md` 每页一个 `\f`，与 `read_file` 的 `splitlines()` 坐标错位可达上百行）；
  `--verify-raw` 用源基线核对丢条，`exit 2` 不得进入解析。
- 切片落盘用 `scripts/extract_criteria.py` 吃 meta「提取区块」清单（⛔ 禁止抄写原文）。
- 两套行号不可混用：`段行号` 属 `uploads/试验方案.md`；**`raw段行号`** 属 raw.md（数百行，
  双轨解析用这套——用 `段行号` 读 raw.md 会越界，`read_file` 对越界**静默返回空串**）。
- `criteria_meta.json` 的 `方案元数据` 至少含方案编号或标题非空（assemble 阠断）。
深水：`references/criteria-extraction.md`；故障 `references/failure-archive.md`。

## §1 入排拆分（核心规则）

### 1.1 四分类体系

| 分类 | 判定依据 |
|------|----------|
| **入选_可从病例获取** | 客观诊断、分期、检验值、影像、用药史、手术史 |
| **排除_可从病例获取** | 同上 |
| **入选_不可从病例获取** | 知情同意、受试者承诺、预后预估、未来计划、研究者主观评估 |
| **排除_不可从病例获取** | 同上 |

### 1.2 拆分判定流程（每条原文按序执行）

1. **识别连接词**：AND 类（"且/并/以及/同时"）与 OR 类（"或/和或/任一/以下之一"）。
2. **AND → 拆**：每个独立分支成子条件，除非是**限定性 AND**（修饰同一事实，判据：
   单看一半无法判定是哪种情况，如「有某病史 **且** 仍需全身治疗」）。
   ⛔ 两类长得像限定性 AND 但**一律必拆**：
   - **跨可获取性边界**（一半客观一半主观）——不拆则 `可从病例获取` 只能标一个值，
     两头丢信息；
   - **跨定性×定量**（一半"阳性/存在"、一半"阈值+数值+单位"）——`转化条件` 只有一组
     `运算符`/`阈值`，装不下两种；⛔ 禁止自创 schema 外字段去装。
3. **OR → 先判异质再决定**。拆不拆的唯一判据：**各分支是否需要查不同的证据位置/匹配字段？**
   需要 → 拆成并行子条件 + 标 `或组`；不需要（同一事实的等价表述/同类列举）→ 写进 `或条件`。
4. **数值范围 → 拆上下限**："18-70岁" → `年龄≥18` + `年龄≤70`。
5. **主条件 + 时间窗 → 拆**：事实条件 + 洗脱期/时间窗各一条。
6. **豁免/除外 → 不拆**：写入所属条件的 `除外` 字段。

**颗粒度基准**：一个子条件 = 一个可独立判定的事实——能否用**一次病历字段比对**得出
「符合/不符合」。能 → 停；不能 → 继续拆。

### 1.3 不拆清单（过度拆分一律并回一条）

- 同一事实的等价表述（单位换算、参考范围变体、同义指标）→ `或条件`；
- 同类列举（"锶-89、钐-153、镭-223 或半身放疗任一"——都查同一份核医学治疗史）→ `或条件`；
- 注释/举例句从主条件剥离另立；语义等价拆两条（"自愿参加"与"签署知情同意书"）；
- "包括但不限于"的列举并入主条件；"除非/除外"拆独立条件（应入 `除外` 字段）。

### 1.4 `或组` 与逻辑关系（拆分后必填，闸 11 机械校验）

| 字段 | 取值 | 要点 |
|---|---|---|
| `逻辑关系` | **枚举只允许** `单条件`/`AND`/`OR分支` | ⛔ 禁自由文本（跨组关系写 `逻辑关系备注`） |
| `或组` | `{原条号}-OR`（多组 `-OR1/-OR2`） | 同组分支同值，组 ≥2 成员 |
| `或组语义` | 入选=`任一满足即整条满足`；排除=`任一触发即整条触发` | **两轨方向相反**；入选漏标/写反会被按 AND 汇总——"满足其一即可"变"必须全部满足"，**错误淘汰患者** |

### 1.5 条件ID 编号

`{IN|EX}-{原条号}[-{子序号}]`：前缀与轨一致；子序号从 1 连续不跳号；一个原条号**要么**
全带子序号**要么**全不带（不得并存）。原条号 `1..末条号` 全覆盖（末条号取
`criteria_meta.json.末条号`，每个原条号至少一个实体）。

### 1.6 转化条件（仅"可从病例获取"类）

字段：`匹配字段`/`运算符`(`≥ ≤ > < = != in 不限`)/`阈值`(数值|文字描述|离散值)/`单位`/
`或条件`/`除外`/`并列条件`/`条件`/`适用臂`/`证据位置`/`同义词` 等。
要点：

- **阈值三档**（与 QC 同口径）：①数值/离散值/区间 + 合法运算符 = 可执行；②原文自带判定要件
  只是写成自然语言 = **可结构化未结构化（阻断）**，修复=拆分或落字段；③要件在外部标准
  （PCWG3/RECIST/CTCAE/NYHA…）或本质相对比较 = `upstream_issues`，首轮归档不占配额。
- ⛔ **每条 `可从病例获取=true` 必须含非空 `同义词`（≥1）与 `证据位置`**（下游按概念取证的
  关键词；空缺=阻断级）。填 `同义词` 至少覆盖 `references/synonym-table.md` 已知易漏项
  （含类别→药名桥接）。
- "不可从病例获取"的 `转化条件`/`日期维度` 为 `null`。
- 日期维度：每分支各自的 `参考事件` + `时间窗` 分别表达。

### 1.7 输出格式（硬规则）

- 每个类目是**以 `条件ID` 为键的 dict（不是数组）**，key 逐字等于条目内 `条件ID`；
- `描述索引` 与 `四分类` 实体**双向一一对应**（改条目同一批改索引；键=主条件ID）；
- 每条 `原文` 在 raw.md **逐字可查**（禁转述/合并两处原文/补词）；
- **分片写入**（每批 ≤15 条），⛔ 禁止单次全量 `write_file`。
深水：完整样例与细则 `references/parsing-rules.md`（唯一权威，render 的内嵌源）。

## §2 质检（两层收敛）

### 2.1 第一层：结构闸（脚本，客观项，自跑到 exit 0）

```bash
python3 /mnt/skills/custom/criteria-parser/scripts/check_track_structure.py \
    --workspace /mnt/user-data/workspace --track {TRACK} [--qc ...qc报告路径]
```

- 解析子代理落盘后**自己跑到 `exit 0` 才返回**；`exit 2` 按点名 problems 自行修
  （只 `str_replace`/`apply_json_patches`，⛔ 禁 `write_file` 重写、⛔ 禁 rm 重建）。
- 16 闸覆盖：顶层结构/条件ID 唯一/前缀与轨一致/子序号规范/描述索引双向/原条号全覆盖/
  QC 目标实体存在/**原地打转探测**（本轮阻断与上轮完全一致=修订无效或问题在上游）/
  `或组` 语义(11)/类目 dict 形态/跨条目污染/**原文忠实性**(9)/阈值分档(12)/
  定性×定量混用(15,阻断)/跨可获取性 AND 未拆(16)。完整判据 `--contract` 取。
- 产物 `criteria_structure_gate_{TRACK}.json`（`exit_code`+`total`）——QC 子代理开工前
  先读它，未过闸自行拒工。⛔ 禁止现写内联脚本顶替、禁止 grep 闸源码猜判据。
- 修订往返预算：全量闸每轨每轮 ≤2 次；改单条确认用 `--only <ID>,<ID>`。
- `--qc` 只在复检时带（闸 7/8/10 只在带 `--qc` 时运行）。

### 2.2 第二层：语义 QC（必须委派 `task(quality-control)`）

- ⛔ **不装配不许派 QC；派时照抄模板的输入清单**（白名单，漏写=禁止读）。派前先装/
  每轮修订后**重装**取证包（`scripts/criteria_qc_bundle.py --out
  criteria_qc_bundle_{TRACK}.md`）——QC 的唯一取证正道，缺失即拒工；
- ⛔ 结构闸 `exit 2` 时禁止派 QC；闸与 QC 任务**不同轮**发出；
- QC 每轮**全量复核**（非增量），报告 `coverage` 两数相等否则本轮无效；
- **首轮定完三档**：阻断级/建议级/upstream 级一次找齐；第 2 轮起只允许标 `fixed` 与纠正档次，
  新增阻断标 `late_discovery`；
- ⛔ QC 结论只由 QC 子代理写；⛔ 禁止「带建议放行/轮次上限」自我放行措辞；
- **轮次纪律**：每轨最多 3 轮（首检 1 + 复检 2 = 2 次修订机会）；轮次只计语义 QC
  （`task(quality-control)` 返回一次 = 一轮），结构闸与整轨重做不占；按轨独立计数，
  一轨触顶**不冻结**另一轨。
- **达 3 轮上限的处置**：仅剩建议级 → 写入 `residual_issues`、该轨 `passed=true` 继续推进；
  仍有阻断级 → ⛔ **冻结该轨**（保留 `criteria_qc_{TRACK}.json` 原样），另一轨继续用完
  自己的预算；`phase2_summary.json` 按轨写 `criteria_qc_status_{IN|EX}`（合取语义见
  `write_phase2_summary.py`）；**两轨都定局后**才发**一次** `ask_clarification` 请用户
  三选一——(a) 按建议修正后重跑该轨 QC（可超 3 轮）/(b) 知情后带病放行（`slim`/`assemble`
  显式加 `--force-qc-unconverged`）/(c) 重新解析该轨。⛔ P3 屏障不放松：必须两轨都
  `passed=true` 才可进判定——带阻断级错误的标准会把错误放大到每个患者的每一条判定。
- **`upstream_issues` 破例核实**：非空时允许回 `uploads/` 核实该句（仅该句、不重新解析），
  核实不了则 `ask_clarification` 请用户裁定；⛔ 禁止再消耗轮次重复同样的修订（结构闸
  原地打转探测会机械拦住）。
- **QC 报脚本/素材缺陷 → 修脚本与派修订并发**（编排决策与 `skill_manage` patch 前置细则
  见 SOUL 原则 5；此处只记域判据）：结构闸已 `exit 0` 而 QC 报「原文不符」→ 错的是 QC
  读到的**素材**，不是产物——照常派本轮修订（prompt 点名假阳性不要改），不要顺势自己改
  本轨标准产物。
- 报告 schema（`blocking_issues[]` 只放 open；`status: open/fixed/upstream`；
  `first_seen_round`；`residual_issues[]` 建议级；`upstream_issues[]` 三档，带原文引用+缺什么+建议核实位置）。
深水：完整清单与报告样例 `references/criteria-qc-checklist.md`。

## §3 修复（按 QC `type` 对号入座）

### 3.1 改写硬规则（违反即任务失败）

- 修订 `criteria_parsed_*.json` **只允许 `apply_json_patches` 对象级形态**（`pointer` 按身份定位
  `/四分类/{类目}/{条件ID}/…`——类目是 dict 无下标）；⛔ `write_file`/`str_replace`/bash 重写
  一律禁止（LLM 重新生成整份会**静默丢条目**且条数看不出来）；
- **一条 `blocking_issues` 一次调用**，该条全部字段同批改完；`add` 只用于新建条目（拆分出的
  新子条件），`remove` 只删 QC 点名条目；看现值用 `{"op":"get"}`；
- 条件ID 变更同批同步 `描述索引`；⛔ 严禁 bash 脚本做语义修订；
- **重做 = 在现有产物上修订**：先读既有条目，正确的原样保留，只改/补点名条目；
  ⛔ 禁止 rm/重建（拆分版被销毁后重写必降级；BashWritePolicy 已机械拒绝 rm/mv）。

### 3.2 按 `type` 处置

| QC `type` | 处置 | 条数 |
|---|---|---|
| **拆分不充分**（含 `运算符=不限`+文本承载判定） | 按 §1.2 拆并行子条件 + 标 `或组`——**改措辞不构成修复** | 1→N |
| 拆分合理性·过度拆分 | 合并回单条，分支入 `或条件`（最危险，见守恒闸） | N→1 |
| 分类错误 | 按可获取性拆两个类目，原条号不变 | 1→2 |
| 与或逻辑错误 | 保持单条，`或条件`/`除外` 改互斥分支表达 | 不变 |
| 证据定位缺失（占位串如"待人工判定"） | 补齐可检索 `匹配字段`/`同义词`/`证据位置` | 不变 |
| 字段不可执行 | 按原文落 `运算符`+数值/离散值 `阈值` | 不变 |
| 覆盖完整性 | 按原文补回实体 | +N |
| 日期维度 | 每分支各自 `参考事件`+`时间窗` | 不变 |

### 3.3 `upstream_issues` 中性化（本轮必做，不是"放着不动"）

三选一批量（一次 `apply_json_patches` 做完全部 upstream，⛔ 不逐条改+逐条跑闸）：
① `可从病例获取` 改 `false` 并移到"不可"类目+备注；② 留原类目但备注写明原文缺什么
（含 `待核实/原文歧义/缺否定词` 之一）**同时**把确定性阈值降为不可执行表达；③ 确属臆造则
删除并同步索引。⛔ `运算符` 不写状态词（用 `不限`，状态词进 `备注`）；⛔ 不反向补全否定词
（回原文核实是编排层的事）。

### 3.4 修订后自检（终点线纪律）

全部改完 → 一次性跑结构闸（不逐条跑）→ 再带 `--qc` 跑一次；**带 `--qc` 的 `exit 0` 就是终点**，
立即写 result 结束（禁止"再确认一遍"复跑）。闸 8 报原地打转（阻断项与上轮完全一致）→
不再试第三种写法，result 报「疑似上游原文缺陷+条件ID+原文引用」交编排层。
条数守恒记账：合并减 N/补拆增 N/跨类目增 N/补回增 N，在 result 回报前后条数与账目。
深水：处置手册全文与委派模板 `references/criteria-repair.md`。

## §4 编排与交付（解析阶段）

> OCR 侧的路线纪律（route 回填/A 失败降级/text sidecar）、在途上限与覆盖率门禁全部由
> `/pdf-image-extractor` 拥有（其 SKILL.md「路线选择」「失败分类与降级」节），本技能只管
> 解析双轨与下面这些解析侧规则。

### 4.1 子任务派发契约（解析轨）

本技能在解析阶段派发的子任务集合（一律先 render 再以 `task(prompt_file=…)` 派发）：

| 任务 | 份数 | 前置 |
|---|---|---|
| 初解析（parse_IN / parse_EX） | 每轨 1 | raw 段行号已落 meta |
| 整轨重做（redo_{TRACK}） | 按需 | 该轨结构闸 `exit 2` 带点名 |
| 语义 QC（qc_{TRACK}_r{N}） | 每轨每轮 1 | 该轨结构闸 `exit 0` + 取证包已装 |
| 修复（repair_{TRACK}_r{N}） | 每轨每轮 1（仅 QC 未过） | 本轮 QC 报告已写盘 |

派发契约——框架已机械保证的部分在此只声明**不重复数字**（并发预算与超发截断由
`SubagentLimitMiddleware` 治理，数值变了文档不跟着漂移）：

- **不超限**：同轮 `task` 调用数不超平台子代理预算——超发被框架**静默截断**
  （不执行也不报错，等于漏派）。
- **不遗漏**：每个 `task` 带 `expected_outputs`（解析/重做=该轨 `criteria_parsed_*.json`；
  QC=`criteria_qc_*.json`）——框架在子代理报 `completed` 前机械探测，缺失判 `failed`
  自动重派一次。
- **不错位**：`prompt_file` 用 render 产物原文件，`description` 与文件名同轨同轮
  （`IN轨修订R2` ↔ `repair_IN_r2.md`）；⛔ 禁止跨轨/跨轮复制 prompt。
- **轨内串行**：同一轨的 QC 与修复不同时在途（修复在途任何人不得碰该轨文件）；两轨间、
  与在途 OCR 互不阻塞。某轨循环终止（QC 通过或达上限）才切包（`slim` 在 QC 通过后的
  **下一轮**单独发出）。

### 4.2 双轨与修复执行

- **双轨并行**：IN/EX 双轨（及在途 OCR）互不阻塞；修订一律委派修订子代理
  （`general-purpose`/`data-extractor`，⛔ 不得用 `quality-control`；⛔ 主代理不得亲做）；
  修订在途时任何人不得碰该轨文件。
- **委派一律 render**（⛔ 禁止手写 prompt）：`render_parse_prompt.py --kind parse|redo|qc|repair`，
  轮次/行号/闸点名机械注入；QC↔修复循环单轮五步与四件套把守见
  `references/parse-orchestration.md`。

### 4.3 切包与收尾

- **切包**：某轨 QC 通过后的**下一轮单独**跑 `parse_pack.py slim`（⛔ 不与该轨 QC 同轮）；
  两轨过后 `assemble` 合成全量包；自检 `IN+EX 条件数 == 汇总统计.子条件总数`。
- **收尾**（两轨 QC 均通过、OCR 侧已全覆盖——覆盖率门禁见 `/pdf-image-extractor`）：按 `parse-orchestration.md`「收尾合并」单次
  bash 机械执行；`phase2_summary.json` 由 `scripts/write_phase2_summary.py` 落盘
  （⛔ 禁手写/占位 stub）。⛔ `criteria_qc_status == "blocked_round_limit"` 时
  `criteria_qc_passed` 必为 `false`，后续阶段一律不得启动。
