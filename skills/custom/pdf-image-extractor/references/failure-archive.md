# pdf-image-extractor 故障档案

⛔ **本文件不含任何新规则**。规则以 `SKILL.md` / `mode-selection.md` 为准；
两处冲突时以规则文件为准并订正本文件。

## 模式确认从未发生

**症状**（会话 `ab76d625`）：整个 run 里 `ask_clarification` 出现 **0 次**。模型直接用 `bash`
回写 `ocr_route="A"`、`route_reason="用户已确认单患者模式…"`，并把该阶段标成 completed。
**用户从未被问过**——`route_reason` 里那句「用户已确认」是模型自己写的。

**为什么危险**：三种处理模式决定的不只是快慢，而是**证据链能不能逐页定位**（模式1 无页块 →
evidence 填不出 `page`/`screenshot_ref`）以及**是否需要患者拆分**。选错的代价不对称：
选错方向要重做整份 OCR，而重做的前提是有人发现选错了——`route_reason` 里写着「用户已确认」
时，没有人会去发现。

**对应规则**：`mode-selection.md`「无默认值」——`classify_uploads.py` 故意产出
`ocr_route: null`，必须被**用户选择结果**覆盖后才可推进；⛔ 禁止按文件数/文件名推断、
禁止「用户没回答就按最快的走」、禁止在 `route_reason` 写未发生的确认。

## 纯文本提问不会中断

**症状**（会话 `459951c1`）：15:04:57 模型用**纯文本**抛出「请回复 1 / 2」（`tool_calls=[]`），
15:05:09 —— **同一个 run 内 12 秒后** —— 就自己把路线落定了。用户 15:06:20 输入 `1` 时，
只能靠回车强制打断已经跑偏的流程。

**机制**：只有 `ask_clarification` **工具调用**会被 `ClarificationMiddleware` 拦截并 `goto=END`。
纯文本没有 tool_call，此时 todos 未完成 → `TodoMiddleware.after_model` 判定「提前退出」
并 `jump_to: model`（每 run ≤2 次），于是模型十几秒后自己继续跑。
**提问看起来发出去了，运行其实没有停。**

**对应规则**：`mode-selection.md`「必须是工具调用」。

## 同轮发出导致中断失效

**症状**（会话 `03a496cc`）：`ask_clarification` 与 `write_todos` **同轮**发出。用户连看到
**3 遍**同一个选择卡片：同轮中断失效但卡片已渲染 → 模型改用纯文本重问（见上一节，同样不中断）
→ `TodoMiddleware` 注入 reminder 后模型才单独发出，中断这才生效。

**机制**：中间件挂在**逐个 tool call** 粒度（`wrap_tool_call`）。同轮若还有别的 tool call，
ToolNode 合并多路输出时这一路的 `goto=END` **不生效**。

**跨会话统计**：同轮发出 4 例 **全部**未中断；单独发出 4 例 **全部**成功。

**对应规则**：`mode-selection.md`「必须单独占一轮」——`ask_clarification` 不得与任何其他
tool_call 同轮，包括 `write_todos`。

## 反复读零字节文件卡死

**症状**（会话 `d1ce04c0`）：流程卡在反复 `read_file` 一个 **0 字节**的
`M016（ZALO）.md` 上，而**同名 PDF 早已拆图完成**——需要的内容一直都在，只是不在那个文件里。

**为什么会循环**：空文件读起来不报错，只是返回空内容。模型把「没拿到内容」理解成
「这次没读到」，于是换 `ls`、换 `glob`、再 `read_file` 一次。
**空文件不会因为多读几次变得有内容。**

**对应规则**：分类阶段已把零字节/sidecar 标为 `ignored` 的项，⛔ 禁止 `read_file` /
`parse_document`；读取返回空内容或文件不存在时，记录一条「跳过原因」后继续下一步，
⛔ 禁止对同一路径重复 read/ls/glob 试探。

---

## 自造目录导致同页重复 OCR

**症状**（两次独立违规，均造成**同一页内容被 OCR 两次**、按页重复计费）：

- `workspace/pagepdfs/`：把每页另存成单页 PDF，再对这些单页 PDF 各跑一次 `parse_document`——
  而该 source 的图片路线已经在跑。
- `workspace/images_ascii/`：为规避中文文件名，复制出一份 ASCII 命名的副本再解析——
  于是原名与副本各解析一遍。

**共同形态**：都不是「解析失败后重试」，而是**新开一条平行路线**，绕过了
「同一 source 路线二选一且只做一次」的去重铁律。目录白名单之所以是硬规则，
就是因为绕道总会先表现为「多了一个目录」。

**对应规则**：`SKILL.md`「解析去重铁律」+ SOUL「目录规范」的目录白名单——
⛔ 禁止创建目录规范未列出的目录。
